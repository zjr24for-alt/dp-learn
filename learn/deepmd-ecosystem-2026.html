DeePMD 生态进展（2026）

一、DeePMD-kit v3.2.0

项内容
pt_expt 后端Array API + torch.export + torch.compile；旧 TorchScript 后端将被废弃
DPA4 / SeZM新描述符+模型，仅 PyTorch，导出走 .pt2
DPA4C紧凑变体（可压缩）
JAX 后端首次支持训练（此前仅推理）
.pt2 推理AOTInductor C/C++，支持 DPA1/2/3
LAMMPSGNN 模型多 rank
训练力 L2-norm / MAE loss、WSD 调度器、LMDB 数据集

已修复：DPA2/DPA3 Hessian NaN、checkpoint 加载、CUDA OOM、近邻表死锁。

已知限制：DPA3 不支持 dp compress —— 会影响部署体积，转 DPA3 前必须先确认。

二、DPA4（arXiv:2606.02419）

性能

  • Matbench Discovery CPS 第 1
  • 参数量 0.48M–25.2M，分 Air（5.1M）/ Plus（8.8M）/ Pro（25.2M）三档
  • 训练成本 ≈ DPA3 的 1/10，单张消费级旗舰卡一天可复现同精度

架构

  • EMFA SO(2) 卷积 + 局部坐标注意力，降维处理转动等变
  • 严格满足平移/旋转/置换对称与能量守恒
  • 原生 ZBL：E = E_NN + E_ZBL，单一标量微分 ⇒ 保守力

原生 ZBL vs 拼接 ZBL（重要区别）

传统做法是把 ZBL 与神经网络势拼接：在切换半径处做平滑过渡。这会产生切换力伪影——dλ/dR × (E_ZBL − E_NN) 这一项没有对应的物理来源。

DPA4 的原生 ZBL 把两者放进同一个可微能量表达式，避免了这个伪影。学习分支在 ZBL 区受 C³ 钳制距离 + source-freeze gate 抑制。

⚠️ 但原生 ZBL 只解决极近距（约 <1 Å）。如果你的问题是中等距离的排斥壁斜率偏低（比如 1.3–1.5 Å 区段力偏软），那一段在 ZBL 生效区之外，仍由学习分支负责——换模型不能替代针对该区间的数据补充。

三、预训练权重与微调

bash
# 下载预训练权重
dp pretrained download DPA4-Neo-OMat24-v20260805

# 微调
dp --pt train input_finetune.json --finetune <ckpt>
  • 支持 DPA-4 LoRA 微调（仅 PyTorch 单任务）
  • ⚠️ 许可需逐个模型卡核对：部分权重（如 OMat24 系列的分子版本）为 cc-by-nc-4.0，禁止商用

什么时候值得走微调路线

预训练微调特别适合近平衡数据饥饿的场景：如果训练集里低力（|F| < 0.05）帧占比极低（如 1–2%），模型在近平衡区会学不好；而大规模预训练基座在近平衡构型上覆盖充分，微调可直接继承这部分知识。

代价：需要 PyTorch 后端 + .pt2，通常意味着重建整套环境分工（训练 / 探索 / dpdata 可能各用不同环境），并重验 LAMMPS 插件、重跑历史基线。

4 模型 ensemble 机制本身不受影响——DPA4 同样可以训多个随机种子。

四、版本选型建议

优先级动作理由
观察稳定版本不必急着升级若当前 TF/常规路线稳定，收益主要集中在 DPA4
评估预训练微调 vs 从零训唯一能直击近平衡数据饥饿的路线
记录转 DPA3 前先确认无 dp compress影响部署体积
